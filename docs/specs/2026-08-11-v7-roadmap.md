# OSRT v7 — Project Review and Roadmap

**Date:** 2026-08-11
**Status:** Roadmap / investigation — **nothing approved, nothing implemented.**
This note reviews the v6 lineage to date, scans the mid-2026 frontier
(DeepSeek V4, GLM lineage, Kimi K3, NVIDIA Nemotron, plus smaller research
models), and proposes a ranked candidate set for what "v7" should be.
**Companions:** `docs/AGENT_HANDOFF.md` (live v6 state),
`docs/specs/2026-07-26-precision-and-sft-objective.md` (§11 open items, §12
rejected list, §14 opportunity catalogue — this note builds on, and does not
re-litigate, those), `docs/specs/2026-06-16-cross-loop-kv-reuse.md` (recursion
probe), `RESEARCH.md` (bibliography through ~June 2026), `LEARNINGS.md` (v5).

## 1. Method

Two inputs feed this roadmap:

1. **An internal review** of everything the v5→v6 lineage has proven,
   disproven, or left open — from the repo's own docs, probes, and training
   history (§2–§3).
2. **An external scan** of what moved at the frontier between the last
   RESEARCH.md refresh (~June 2026) and today, focused on the model families
   the user named: DeepSeek V4, GLM 5.x, Kimi K3, the latest NVIDIA Nemotron
   releases, and the "Inkling" line (§4–§6).

The synthesis (§7–§9) applies the repo's standing filter: **measure before you
build; tokens are the bottleneck; a lever is only worth taking if it survives
contact with the ~601M-scale budget reality.** v7 should be the smallest set of
changes that converts what v6 *proved* into a model that actually *performs* —
not a grab-bag of 2026 features.

## 2. v6 report card — what the project has actually established

### 2.0 Where the pipeline actually is (2026-08-11, verified against HF)

`docs/AGENT_HANDOFF.md` (2026-07-06) describes midtrain3 as "no surviving
checkpoint yet". That is now stale. The private checkpoint repo
(`HallD/osrt-v6-ckpt`) shows the **entire §8 roadmap of the handoff has been
executed end-to-end** since then:

| stage | artifact evidence | notes |
|---|---|---|
| midtrain3 | `osrt_v5_midtrain3_step_12600.pt`, `_final.pt`, rescue at 12038 | the full 12,600-step / +3.4B-token plan → base is at ~1× Chinchilla (~5.6B tokens) |
| SFT v3 | `osrt_v5_sft_v3_final.pt`, `data/sft_v3.jsonl` (~207MB) | post-midtrain3 SFT rebuild |
| SFT v4 | `osrt_v5_sft_v4_final.pt`, `_step_1600.pt`, `data/sft_v4.jsonl` + val split | second SFT iteration |
| soup | `osrt_v5_sft_v4_soup_1200_1400_1600_1800.pt` | checkpoint-soup polish stage reached |
| GRPO v6 | `grpo_v6_step_10..400.pt`, `data/grpo_prompts.jsonl` | RL stage ran ≥400 steps |
| GRPO v6b | `grpo_v6b_*`, `grpo_v6b_s7x200_*` + `*_ema_*` | second RL round, **with weight-EMA** (a §14.3 recommendation, evidently adopted) |

Two consequences for this roadmap:

1. **v6 is pipeline-complete.** Pretrain → midtrain×3 → SFT×4 → GRPO×2 →
   soup all exist. Whatever the final GSM8K/eval numbers say (they live in
   W&B, run `codhe-synextra/osrt` — not readable from this session; confirm
   before locking v7 decisions), the v6 *program* has run its course. This is
   the right moment to plan v7 rather than keep extending v6 ad hoc.
2. **The runs have outpaced the committed code.** No `SFTv3Config` /
   `SFTv4Config` / `grpo_v6b` / soup configs exist in `src/osrt/train_config.py`
   on `main`, and `CLAUDE.md`/`AGENT_HANDOFF.md` describe a two-cycles-old
   state. Whatever drove sft_v3/v4 and grpo_v6/v6b lives outside git.
   **v7 hygiene item #1: land those configs + a results table before the
   details evaporate** — this repo's whole methodology depends on the paper
   trail.

### 2.1 Proven (keep; these are the assets)

- **The architecture trains, and the recursion is real.** The full stack —
  3 physical blocks × 6 loops (18 effective layers), 1 shared + 8 routed
  top-2 experts, GQA 24q/8kv over an MLA-style compressed-latent KDV cache,
  rank-256 native HRA per effective layer, Muon+AdamW hybrid — pretrained,
  midtrained (×2), and SFT'd without loop collapse or router collapse.
  The 2026-06-16 probe (`docs/specs/2026-06-16-cross-loop-kv-reuse.md` §6)
  showed per-loop KV latents are *distinct* and adjacent-loop CKA movement
  contracts monotonically (block 0: 0.30 → 0.17 → 0.07 → 0.05 → 0.05) — a
  **contracting fixed-point iteration**, i.e. non-degenerate iterative
  refinement. This is the single most important scientific result the project
  owns: the differentiator (sparse MoE + depth recurrence + Muon) is not a
  degenerate combination.
- **The stability stack works.** QK-norm, sandwich RMSNorm, per-loop routing
  accounting, balance-bias controller + Switch aux + z-loss, SwiGLU clamp,
  aux-loop losses (0.05) + loop dropout: v5's three signature failures (loop
  collapse, router collapse, logit blow-up) did not recur in v6 training.
- **The training infra is genuinely portable.** One `run_training` loop with
  three front-ends (Modal / Colab / bare CUDA), cross-session chaining via HF
  checkpoint sync (`scripts/hf_ckpt_sync.py`), W&B as the reliable monitor.
  The nine landmines in `AGENT_HANDOFF.md` §5 are all diagnosed and fenced.
  Tree is green as of this note: 215 passed / 1 skipped on CPU.
- **Format teaching works.** SFT v2 produced `format_ok = 1.0` — clean
  `<|think|>…<|/think|><|answer|>…<|/answer|>`, no loop-collapse generation.
  Eliciting *format* from this base is a solved problem.
- **Compute-bound identity confirmed.** The architecture runs at ~69% of H100
  throughput on an RTX PRO 6000 with ~half the bandwidth — recursion reuses
  weights, KDV shrinks the cache. The design thesis (spend bandwidth savings
  on compute) held on real hardware.

### 2.2 Disproven or failed (v7 must not repeat)

- **"SFT/GRPO can rescue an undertrained base" — disproven.** GSM8K stayed at
  ~0.04–0.06 across SFT v1 and v2 despite a verified-reasoning corpus. The
  diagnosis (`AGENT_HANDOFF.md` §2): the base has seen **~2.2B tokens ≈ 0.4×
  Chinchilla for 278M active params** — models this size that reason saw
  trillions. Post-training elicits; it does not create.
- **Cross-loop KV reuse — rejected by measurement** (mean injected rel-L2
  ≈ 1.04; loops carry distinct KV). The 6× bandwidth prize is off the table
  for this trained model; any future attempt must be *trained-in*, not
  retrofitted.
- **Attention sink — dropped** (memory blow-up at seq 8192, no demonstrated
  benefit).
- **The token-budget arithmetic was the plan's weakest link.** v6's design doc
  targeted 1.5–3T tokens; the funded reality delivered ~2.2B before midtrain3.
  The gap between the design's data ambition and the drip budget is the
  defining constraint of the whole project, and v7 planning has to start from
  it rather than rediscover it at the end.
- **mHC's Sinkhorn mixing was a measured throughput tax** (user report,
  2026-08-11: tok/s was "really really slow until optimised", with Sinkhorn
  the main suspect). Each effective layer runs **two** mHC sub-blocks —
  attention and FFN (`model.py:1370`, `:1379`) — so a forward performs
  **36 Sinkhorn projections × 20 iterations each**
  (`mhc_sinkhorn_iters=20`) when 3–5 typically converge — the 2026-07-26
  note had already flagged profiling it (§11). Combined with the unresolved NaN question (§2.3.1), mHC in its
  current form is on notice: v7 either makes it cheap (3–5 iters, or a
  cheaper non-expansive constraint) or drops the 4-channel stream entirely.

### 2.3 Open / unresolved (v7's cheapest wins live here)

From `2026-07-26-precision-and-sft-objective.md` §11/§14 and README §13, still
open as of this note:

1. **mHC at scale** — the preset ships `use_mhc=True` but CPU pre-flight saw
   gradient amplification + NaN under sustained training
   (`presets.py:38-42`); the GPU A/B (`n_hc ∈ {4,2,off}`) has not run. v6 is
   *carrying an unvalidated stability risk in its default config.*
2. **Chinchilla is ill-defined for a 6×-weight-reused sparse model** — the
   scaling ladder + µP transfer (§14.3) that would pin the real token target
   has not run. Every budget decision inherits this uncertainty.
3. **Cosine → WSD (trunk-and-branch)** for drip training — catalogued, not
   adopted; every extension still pays the re-warm tax.
4. **Data fast-forward across resumed sessions** — possible silent
   stream-head oversampling; one W&B log line would settle it (§14.1).
5. **Speculative decoding via the loop-3 draft** — acceptance rate never
   measured; per-loop self-distillation (§14.5) that would raise it not
   started.
6. **Loops × blocks trade-off** (3×6 vs 4×4 vs 2×8 at fixed compute) — never
   ablated; the probe result (convergence by loops 4–5) *suggests* the last
   loops are cheap to trim, but only at representation level, not logits.
7. **Logit-level KD is blocked by the custom 65K tokenizer** — flagged in
   §14.9(b) as "a real cost of the tokenizer worth weighing in any v7
   decision."
8. **Recent opt-in features await A/B:** SiTU-GLU (Kimi K3 §2.3.2 —
   `config.py:67`, param-free activation swap) and per-head Muon (Kimi K3
   §2.5 — `muon.py:90`) are implemented, tested, default-off, unmeasured.

### 2.4 Standing constraints (unchanged by any v7 ambition)

- **Budget:** ~$120/month Modal drip + Colab units + one always-on GPU box.
  1× Chinchilla for the current model ≈ 3 months of drip.
- **Deliverable:** a working architecture + pipeline + as much pretraining as
  budget allows — not a frontier model.
- **Naming debt:** repo/preset names (605M/A288M/A269M) predate the corrected
  601M/278M count; `compute_budget.py` is the only trusted source.

## 3. The strategic question v7 must answer

v6's bottleneck is not architecture — it is **tokens through the machine**.
Any v7 that increases cost-per-token without either (a) increasing
learning-per-token or (b) unlocking cheaper tokens is a step backwards. That
framing sorts every candidate change into three buckets:

- **B1. More learning per token** — data quality/curriculum, distillation,
  MTP evolution, objective changes, optimizer efficiency.
- **B2. More tokens per dollar** — throughput (fp8/precision, loop
  curriculum, seq-length policy), scheduler (WSD → no re-warm waste),
  stream hygiene (no oversampling), free/granted compute.
- **B3. More capability per parameter at deploy time** — attention/KV
  efficiency, spec decode, early exit, quantization.

The external scan below is read through exactly this lens.

### 3.1 Hard requirements set by the user (2026-08-11)

These are requirements, not candidates — every §7 proposal must satisfy
them:

1. **Single-GPU training fit, comfortably.** v7 trains on **one H100 80GB
   or one RTX PRO 6000 96GB**. v6 needed ~58GB at batch-6/seq-4096 with
   grad checkpointing — workable but tight, and it forced micro-batch
   gymnastics on 40GB cards. "Comfortably" means sizing the v7 model +
   optimizer + activations so the H100 case has real headroom (target:
   ≤~60GB at the standard recipe, leaving room for bigger batch, longer
   seq, or in-loop eval), and the RTX PRO 6000 (compute-rich,
   bandwidth-poor — proven at ~69% of H100 on this arch) stays a
   first-class target. Consequence: **total params stay in the 600M–1B
   band**; the shape can change, the memory envelope cannot.
2. **Revisit expert granularity: more, smaller experts.** v6 chose 8×3840
   (top-2, 25% density) deliberately deferring the fine-grained thesis to
   "16B+ scale" — the user now wants that reopened. The 2026 evidence is
   on their side: every scanned family is fine-grained (V4-Flash 256
   experts top-6; Nemotron Nano 128 top-6 **at only 3.2B active**; Inkling
   256+2 top-6; see also §5). Fine-grained also un-defers the §8 adaptive
   top-k idea (rejected at E=8, explicitly deferred to E≥32).
3. **The tokenizer is not good enough.** First-hand quality complaint, on
   top of the already-documented structural cost: the custom 65K BPE
   **blocks logit-level KD from every open teacher** (2026-07-26 note
   §14.9b). v7 should treat the tokenizer as replaceable, and weigh
   adopting a proven open tokenizer whose teacher family we would
   distill from (§7).
4. **The residual stream must not tax throughput.** Sinkhorn-20 across 36
   projections per forward (2 mHC sub-blocks × 18 effective layers) was a
   measured tok/s drag (§2.2). Whatever v7 does about mHC — fewer
   iterations, cheaper constraint, or removal — the residual stream
   returns to near-zero overhead.

## 4. External scan: DeepSeek V4 lineage

Researched 2026-08-11. RESEARCH.md §2 was written against the **April preview
+ HF card**; the **full V4 tech report is now out (arXiv 2606.19348, Apr
2026)**, plus two research threads (mHC paper, Engram) and a Flash refresh
(V4-Flash-0731, Jul 2026). R2 never shipped — the R-series was absorbed into
V-series reasoning-effort modes (Non-think / Think-High / Think-Max).

### 4.1 What the full report confirms (that v6 already bet on)

OSRT v6 adopted several V4-preview features on faith; the report now
validates each at 1.6T-param scale, with exact numbers:

- **mHC, n_hc=4, 20 Sinkhorn iterations** — production config (mHC paper:
  arXiv 2512.24880; −0.021 final loss at 27B, +2.1 BBH). **Critically: the
  6.7% time overhead DeepSeek quotes is *after* kernel fusion + recompute +
  DualPipe engineering.** OSRT has none of that — which squares with the
  user's observation that Sinkhorn dominated tok/s until optimised. The
  constraint is validated; *our implementation cost* is the problem (§7).
- **Muon exact recipe:** Nesterov 0.95, wd 0.1, update-RMS 0.18 rescale,
  hybrid Newton–Schulz 10 iters (8 fast + 2 stabilizing (2,−1.5,0.5)),
  AdamW (ε=1e-20) for embeddings/head/norms **and mHC static
  biases/gates** — worth auditing `build_param_groups` for that last split.
  Notably **no QK-Clip**: RMSNorm on Q/KV entries suffices (matches OSRT's
  QK-norm choice).
- **sqrt(softplus) router affinity, aux-loss-free bias speed 0.001, plus a
  small sequence-wise balance loss at 1e-4** (OSRT has the field
  `router_seq_balance_loss_coeff=0.0` — V4 says turn it on, tiny).
- **Hash routing for the first 3 MoE layers** (token-ID hash) — OSRT's
  `hash_routing_blocks` exists but ships off.
- **MTP depth-1, loss 0.3 → 0.1 at LR decay** — OSRT runs 2 heads at 0.3
  flat; the anneal-to-0.1 refinement is free.
- **SwiGLU clamp ±10** — exactly OSRT's `swiglu_clamp=10.0`.
- **Anticipatory routing is a spike-*recovery* mode, not always-on** —
  engaged around detected loss spikes with stale-parameter routing, then
  reverted (~20% overhead while active). Pairs with the §14.3(b) spike
  auto-rollback idea.

### 4.2 What's genuinely new since RESEARCH.md

- **CSA/HCA in full detail:** the lightning indexer now scores **4×
  sequence-compressed** KV entries (FP4 QK), top-k=512/1024 compressed
  entries, MQA over shared latent entries, **plus a parallel 128-token
  sliding-window branch + attention sink**, RMSNorm on Q/KV, partial RoPE
  (last 64 dims). MLA per-layer latent KV survives only as DNA (low-rank Q,
  latent-style shared entries). Sequence-dim compression replaced
  channel-dim compression as the KV lever.
- **Engram (arXiv 2601.07372, Jan 2026) — the verified "DeepSeek engram":**
  an O(1) **hashed N-gram embedding lookup** (2–3-grams, multiplicative-XOR
  multi-head hashing) + context-aware gating, inserted at 1–2 shallow
  layers. Headline: a **U-shaped sparsity-allocation law — reallocating
  ~20–25% of the sparse budget from MoE experts to lookup memory wins at
  iso-params/iso-FLOPs** (MMLU +3.0, GSM8K +2.2, BBH +5.0 at 27B), and CKA
  shows shallow Engram layers doing the work of much deeper MoE layers
  ("effective depth" gain). Table can offload to host DRAM at ≤2.8%
  throughput cost. **Not in V4** (named as future work there).
- **xHC (arXiv 2607.14530, third-party, Jul 2026):** diagnoses mHC's n>4
  saturation (single write-back starves streams; O(n³C) mapping cost) and
  fixes it with temporal-conv write-back augmentation + k-of-N sparse
  stream updates. Also: mHC-as-PEFT (2607.18130) — adapting residual
  mixers instead of weights, adjacent to HRA.
- **V3.2's MoE-RL stabilizer kit** (carried into V4's specialists): **Keep
  Routing** (cache sampling-time expert paths, enforce them during policy
  updates — "crucial" for MoE RL), unbiased K3 KL estimator, off-policy
  negative-sequence masking, keep-sampling-mask.
- **OPD is now the whole consolidation stage:** specialists via SFT+GRPO,
  then **reverse-KL full-vocabulary distillation on the student's own
  rollouts** unifies them (the README §10b.1 plan, now the shipped V4
  pipeline — and independently NVIDIA Ultra's "MOPD", §6.1).

### 4.3 What this means for OSRT

1. Every "adopted on faith" v6 feature survived scale contact — the
   *choices* were right; the open problems are cost (mHC) and measurement.
2. **Engram is the single most interesting new idea for a recursive
   model:** loops spend shared capacity reconstructing static facts every
   pass; a hashed lookup sidecar supplies facts for free and lets the loops
   do composition. It attacks exactly the knowledge-vs-skill trade
   (§6.2/§6.3) from the memory side, at near-zero FLOPs.
3. The **V4 attention pattern is scale-independent**: compressed-global +
   sliding-window + sink over the existing latent cache would cut
   long-context cost ~4× without the indexer (indexer only pays >16K).
4. **MoE-RL hygiene (Keep Routing et al.)** plugs straight into the
   existing GRPO stack and may explain past RL instability cheaply.

## 5. External scan: GLM 5 / 5.2 (Zhipu) and Kimi K3 (Moonshot)

Researched 2026-08-11. These two labs matter doubly to OSRT: they are the
production home of the Muon lineage, and the repo has *already* imported two
K3 report features (SiTU-GLU §2.3.2, per-head Muon §2.5) behind default-off
flags.

### 5.1 GLM-5 (Feb 2026, 744B/A40B, arXiv 2602.15763) and GLM-5.2 (Jun 2026)

- **Switched GQA → MLA ("MLA-256")** and closed the Muon-vs-MLA gap with
  **"Muon Split"**: the fused MLA up-projections are split per attention
  head and Newton–Schulz runs on each head's momentum separately. Their
  ablation says this per-head treatment is *what makes* Muon+MLA match or
  beat GQA — the strongest possible endorsement of the repo's new
  `per-head Muon` flag (same idea, independently derived as K3 §2.5).
- **Adopted DeepSeek's DSA** (lightning indexer) on top of MLA; GLM-5.2
  adds **IndexShare** (one indexer reused across every 4 sparse layers)
  for a usable 1M context at 2.9× lower per-token indexing cost.
- **Ablated and REJECTED cheap linear/sliding-window attention:**
  RULER@128K 75.3 dense vs 44.9 SWA-interleave, 67.0 SimpleGDN. The
  warning for OSRT: cut-down linear attention loses retrieval — hybrids
  only work with the *full* KDA-style recipe (see §5.2).
- **MTP with parameter sharing across 3 MTP layers** (fixes the V3
  train/inference discrepancy); spec-decode acceptance 2.76 tokens.
- Post-training: SFT → reasoning RL (GRPO + IcePop mismatch correction;
  **DSA indexer frozen during RL**) → async agentic RL (token-in/token-out
  gateway, double-sided importance sampling) → general RL → **on-policy
  cross-stage distillation** to consolidate — *policy-space* consolidation,
  explicitly instead of weight merging. RL infra (`slime`) is Apache-2.0.
- GLM-5.2 was assessed as the strongest open-weights model at release
  (first open model at 50 on the AA index was GLM-5). All MIT.
- Small-model note: GLM-4.7-Flash (30B-A3B, Jan 2026, MIT) is their
  current small MoE; no GLM-5-generation small model yet.

### 5.2 Kimi K3 (Jul 2026, 2.8T/A104B, arXiv 2607.24653) and the K2 lineage

- **Hybrid KDA:MLA at 3:1** (69 KDA + 24 gated-MLA layers): KDA = delta
  rule + channel-wise forget gate + lower-bounded log-decay + sigmoid
  output gate + short conv, from the Kimi Linear paper (2510.26692 —
  1.16× compute-optimal vs full-MLA, 6× decode @1M, with a full ablation
  grid at 48B-A3B). **Gated MLA layers use NoPE — no RoPE anywhere**; the
  decay gates carry position.
- **Stable LatentMoE:** 896 routed experts top-16 + 2 shared (~1.8%
  routed density); routed experts run in a **compact latent space** with
  an **RMSNorm between expert aggregation and up-projection** — a one-line
  routed-branch stabilizer. (Same latent-experts idea as Nemotron's
  LatentMoE, §6.1 — two labs converged.)
- **SiTU-GLU** — the smooth β·tanh(x/β) cap on gate and up branches
  (already in this repo behind `situ_glu`).
- **Quantile Balancing (QB):** aux-loss-free balancing where the
  per-expert bias is set **directly from the router-score quantile
  matching the target load** (histogram over the global batch) —
  deterministic, hyperparameter-free, "zero dead experts". A drop-in
  upgrade candidate for OSRT's heuristic ±γ bias controller, and most
  valuable exactly where OSRT lives (small expert pools, where one dead
  expert = 12.5% of capacity).
- **Per-head Muon** (≡ GLM Muon Split), **MuonClip retired**: K2's QK-Clip
  is gone in favour of norm-based control. Independently, **QK-Normed MLA
  (Ant Group, arXiv 2606.16310) validates QK-norm > QK-Clip at 400M
  params / 100B tokens** — OSRT-scale evidence for OSRT's existing choice,
  plus an exact factorization for keeping QK-norm inside a latent decode
  path at ~1.4% overhead.
- **QAT from SFT onward: MXFP4 weights / MXFP8 activations** — all
  reported benchmarks are at deployed precision.
- Post-training: SFT → RL over **nine specialists (3 domains × 3
  reasoning-effort levels)** → **MOPD** (multi-teacher on-policy
  distillation, clipped per-token teacher–student log-prob reward) into
  one model. MTP head is fine-tuned into an EAGLE-3-style draft model.
- Third-party MOPD paper (Xiaomi, 2606.30406): **weight merging measured
  worst-in-class for consolidating specialists** (0.33–0.86 normalized vs
  MOPD 0.94); same-origin teachers (shared SFT init) are the stability
  precondition. Note this does *not* contradict Nemotron's +2–4pt
  checkpoint merging (§6.1) — that merges a sliding window of *the same
  run*; what's dead is merging *different specialist models*.

### 5.3 What this pair means for OSRT

1. **Graduate the two flags now justified at scale:** per-head Muon
   (GLM says it's the reason Muon+MLA works) and SiTU-GLU (K3's expert
   activation). Both are implemented and tested — they need an A/B, not
   engineering.
2. **Quantile Balancing** is the single best new router idea for small-E
   MoE — deterministic and hyperparameter-free where OSRT currently tunes
   `update_rate/ema_rate/max`.
3. **The fine-grained + latent experts direction is unanimous** (K3 896,
   GLM 256, V4 256–384, Nemotron 128–512, Inkling 256) — supports the
   user's "more smaller experts" requirement; latent-space experts are the
   param-efficiency variant worth one ladder slot.
4. **Hybrid linear attention is real but all-or-nothing** — Kimi Linear's
   full recipe wins; GLM's ablation shows half-measures lose retrieval.
   At OSRT's 4–8K target context this is a stretch experiment, not a
   default (§7).
5. **Consolidation is policy-space, not weight-space** — for v7's
   multi-domain post-training, plan OPD/MOPD-style distillation between
   same-origin specialists; keep same-run checkpoint souping.
6. **NoPE + decay-gated position** is how two labs now do length
   generalisation; OSRT's RoPE remains fine at 8K, but this removes any
   pressure to adopt exotic RoPE scaling in v7.

## 6. External scan: NVIDIA Nemotron 3 and Inkling (Thinking Machines)

Researched 2026-08-11 (web + alphaXiv sweep; primary sources cited).
RESEARCH.md §12 covered Nemotron-CC and noted "Nemotron 3 Ultra" only as a
too-slow teacher; the picture is now much bigger.

### 6.1 Nemotron 3 family (Dec 2025 → Jul 2026) — confirmed

Nano 30B-A3B (arXiv 2512.20848), Super 120B-A12B (2604.12374), Ultra
550B-A55B (2606.15007), family overview (2512.20856), Nano Omni (2604.24954),
Puzzle-75B-A9B compression (2607.04371). All open-weights (Nemotron Open
Model License) with **>10T tokens of the training data released openly** —
the most complete open release at frontier-adjacent scale.

Architecture:
- **Hybrid Mamba-2 + sparse-attention layout.** Nano keeps only **6
  full-attention (GQA) layers out of 52** as "global anchors"; Mamba-2
  carries the sequence elsewhere. **No positional embeddings at all** —
  Mamba supplies position implicitly, which is how 1M-context extension
  avoids RoPE OOD. 3.3× decode throughput vs Qwen3-30B-A3B.
- **MoE everywhere else:** 128 experts top-6 (Nano), aux-loss-free
  balancing, squared-ReLU experts, untied embeddings.
- **LatentMoE (Super/Ultra):** route + run experts in a down-projected
  latent space; reinvest the saved bandwidth into ~4× more experts at the
  same inference cost. Beats iso-cost standard MoE on every eval reported.
- **MTP heads** (shared-weight): +~2.4% avg quality at ablation scale and
  ~97% 2-token draft acceptance for self-speculative decoding; "MTP
  healing" post-stages retrain the head on-policy.

Training:
- **NVFP4 end-to-end pretraining is production reality** (Super: 25T tokens;
  Ultra: 20T; recipe in arXiv 2509.25149 — keep last ~15% of layers +
  QKV/out projections high-precision, Hadamard transforms + stochastic
  rounding). Requires Blackwell; loss gap <1% vs BF16.
- **WSD with a two-phase curriculum** (broad diversity ~90–95% of tokens →
  high-quality/synthetic anneal) across the whole family.
- **Checkpoint merging during the stable phase: +2–4 points avg across 12
  benchmarks** — weighted averaging over a sliding window of checkpoints.
- **Iterative Puzzle compression:** (prune expert channels → reduce top-k →
  shrink SSM state) × 3 rounds, each healed by short KD; iterative beats
  one-shot; ~2× throughput at near-parent accuracy.

Post-training:
- SFT → **simultaneous multi-environment RLVR** (staged RL was *less*
  stable and more reward-hackable), GRPO with masked importance sampling,
  **MoE router frozen during RL**, difficulty-based curriculum sampling.
- Ultra adds **MOPD — multi-teacher on-policy distillation** (>10 domain
  specialists, reverse-KL on student rollouts, PPO-style clipping) — the
  same pattern README §10b.1 planned from the V4 preview, now productionised
  by NVIDIA.
- **Reasoning on/off + token-budget control trained purely via SFT data**
  (model completes answers from truncated thinking traces); Ultra's
  medium-effort mode: ~2.5× fewer tokens for ~7% accuracy drop. RLHF adds
  group-relative **length-control reward: −30% verbosity at no accuracy
  cost**.

### 6.2 Inkling / Inkling-Small (Thinking Machines Lab) — confirmed

"Inkling" = the open-weights multimodal MoE family from Thinking Machines
(Mira Murati's lab): **Inkling** 975B/A41B (2026-07-15, Apache-2.0) and
**Inkling-Small** 276B/A12B (2026-07-30). Blog + model card only, no arXiv
report. Headline facts:

- **Muon + Adam hybrid at 975B/45T-token scale** — exactly OSRT's optimizer
  split (Muon on large 2D matrices, Adam elsewhere), with one refinement:
  **weight decay coupled ∝ LR²** so decay follows the schedule. This is the
  strongest at-scale validation the Muon-hybrid bet has received.
- Attention: **5:1 sliding-window:global interleave**, 8 KV heads,
  **relative positions instead of RoPE** (length extrapolation), short
  convolutions (SConv) on attention projections and residual branches.
- MoE: 256 routed + 2 shared experts, top-6, sigmoid router,
  DeepSeek-style aux-loss-free bias.
- MTP layers for self-speculative decoding; encoder-free multimodality;
  7-level `reasoning_effort` dial; async RL at 30M+ rollouts.
- **Inkling-Small beats its own 975B parent on agentic/skill evals**
  (SWE-bench Verified 80.2 vs 77.6, ARC-AGI-2 40.1 vs 36.5) while losing
  −23 pts on SimpleQA factuality — the cleanest public datapoint that
  **small-active models trade knowledge, not skill**. Debuted as the
  leading US open-weights family on the AA index (41 vs Nemotron Ultra 38).

### 6.3 What this pair means for OSRT

1. The **optimizer bet is settled** (Inkling), and the **WD ∝ LR² coupling**
   is a free recipe upgrade to trial.
2. The **skill-vs-knowledge trade** (Inkling-Small) is directly encouraging
   for a 278M-active reasoning-first model: prioritise reasoning/agentic
   density in the anneal, delegate facts to tools/retrieval.
3. **Attention is being deleted, not just compressed** — both labs converge
   on "a few global-attention anchors + cheap sequence mixing" (Mamba-2 or
   SWA+SConv). OSRT's recursive analog: make attention heterogeneous
   *across the 3 physical blocks* (e.g. one full-attention anchor block +
   two cheap-mixer blocks), which multiplies through the 6 loops.
4. **Checkpoint merging in the stable phase** and **reasoning-budget
   control via SFT data** are near-zero-cost adoptions.
5. **Router frozen during RL + simultaneous multi-env RLVR + length-control
   reward** are directly applicable to the existing GRPO stack.
6. NVFP4 pretraining is real but Blackwell-only — park for v8; selective
   FP8 PTQ (keep attention anchors BF16) is the deployment-quant pattern to
   copy now.

## 7. Candidate set for v7 (ranked)

One striking meta-result of the scan: **v6's bets aged well.** Muon-hybrid,
QK-norm-over-QK-Clip, aux-loss-free balancing, sqrt(softplus), SwiGLU clamp,
MTP, fine-grained-MoE-direction, OPD — every one is now validated at
frontier scale, several by multiple labs independently. v7 is therefore not
a re-architecture; it is a **re-grain + re-tokenize + cost-fix + recipe
upgrade** on a proven core. The recursion (3 blocks × N loops) remains the
differentiator — still no released model combines sparse MoE with depth
recurrence.

### 7.3 Tier 2 — the four headline moves (this IS v7; each behind a gate, §9)

**A. Fine-grained expert re-grain (user requirement 2).**
Iso-param, iso-active re-slice of the routed pool per block:
`8 × h3840, top-2` → **`32 × h960, top-8`** (identical 141.6M routed
params/block and identical active FLOPs; 4× finer routing at the same 25%
density). Conservative fallback: `16 × h1920, top-4`. Pair with QB
balancing (1.4) and per-loop routing telemetry (already built). Un-defers
the E≥32 world; **adaptive top-k stays deferred** — the fixed-shape/compile
objections (§12 of 2026-07-26 note) still hold. Optional ladder slot:
K3/Nemotron-style **latent-space experts** (route + compute in a ~half-width
latent) as a param-efficiency variant. Risk to measure: smaller per-expert
GEMMs → lower arithmetic intensity; grouped-GEMM must be re-benchmarked at
E=32 on both target GPUs.

**B. Tokenizer replacement (user requirement 3) — the single biggest
strategic unlock.**
The custom 65K BPE has a first-hand quality complaint AND blocks
logit-level KD from every open teacher (§14.9b). Candidates:

| option | vocab | tied-embed @1536 | unlocks logit-KD from | notes |
|---|---|---|---|---|
| keep custom | 65,536 | 100.7M | nobody | status quo; quality complaint stands |
| retrain custom on better corpus | 65,536 | 100.7M | nobody | fixes quality, not the KD blockade |
| **SmolLM3's tokenizer** | 49,152 | **75.5M (−25M)** | SmolLM3-3B (Apache-2.0, strong open reasoning teacher, dual think/no_think contract similar to ours) | frees ~25M params for experts/Engram; verify digit handling, fertility on our math/code mix, special-token mapping |
| LFM2's tokenizer | 65,536 | 100.7M | LFM2 family (350M–2.6B) | drop-in size (v6's ratios were modelled on LFM2 anyway); teacher family weaker at reasoning than SmolLM3-3B |

Recommendation to test first: **SmolLM3** — pick the teacher, then take its
tokenizer; the point is dense distillation (LFM2-style decoupled top-K KD
gives ~32× denser supervision per token — exactly what a token-starved
budget needs, and it was README §10a plan blocked only by the tokenizer).
Both candidate tokenizers need the bake-off in §9-G2 before any decision.
Consequence either way: v7 restarts pretraining — which is the honest
moment to also fix the §3.1 requirements in one go.

**C. Residual stream: make mHC cheap or turn it off (user requirement 4).**
Options in order of preference: (i) `mhc_sinkhorn_iters` 20 → 3–5 (mHC
paper itself notes typical convergence; DeepSeek's 6.7% overhead came
*with* fused kernels we don't have); (ii) replace Sinkhorn with row-softmax
mixing (drops the doubly-stochastic guarantee; keeps multi-stream); (iii)
`use_mhc=False` — v5 proved plain residual + sandwich norms survives 18
effective layers. Decision rule in §9-G1: **≤5% measured tok/s overhead on
the RTX PRO 6000 or mHC is off in v7.** Watch xHC (2607.14530) for the
n>4 fix, and mHC-as-PEFT (2607.18130) as a later serving idea.

**D. Single-GPU sizing envelope (user requirement 1).**
Hold total in the **575–700M band**, active ~250–280M, seq 4096, and
require the standard recipe to fit **≤~60GB** (batch ≥6, grad-ckpt) so H100
has headroom and RTX PRO 6000 gains batch room. The §8 strawman lands at
~574M/~57GB. Levers if tight: mHC off (frees activation stream), micro-batch
knobs (proven), fused-CE already in place.

### 7.4 Tier 2½ — one bold architecture experiment (single ladder slot)

**Engram sidecar memory (DeepSeek, 2601.07372).** Hashed N-gram lookup +
gated injection at 1–2 shallow points. Why it fits OSRT specifically: the
U-shaped allocation law says sparse budget is better split between experts
and lookup memory; the effective-depth result (shallow Engram ≈ deep MoE
layers) *composes with recursion* — loops stop re-deriving static facts and
spend depth on composition; and Inkling-Small's skill-vs-knowledge trade
(§6.2) says knowledge is exactly what a 250–280M-active model lacks.
Options: reinvest the ~25M embedding savings on-GPU, or a larger
CPU-offloaded table (paper: ≤2.8% throughput cost). **Do after the
tokenizer decision** (N-gram IDs are tokenizer-dependent). Gate: ladder A/B
at ~150M scale vs iso-param expert-only control.

### 7.5 Tier 3 — training recipe

1. **Scaling ladder + µP transfer first** (§14.3 of the 2026-07-26 note,
   now upgraded from "opportunity" to **the gating instrument for every
   Tier-1/2 choice**): ~3 sizes (50/100/150M) × 3 token budgets on the
   always-on box; re-derives the Chinchilla yardstick for a 6×-weight-reused
   sparse model before the next three months of spend.
2. **Two-phase WSD data curriculum** (diversity ~90% → high-quality anneal)
   with the **refreshed Nemotron open sets** (CC-v2.1, CC-Code-v1,
   Pretraining-Code-v2, Specialized-v1, Post-Training 3.0) — the v6 mix
   already leans Nemotron; v2 sets are bigger and cleaner. FineWeb-Edu
   `int_score≥4` filter; deliberate ~4-epoch reuse of best slices.
3. **Anneal-phase logit KD from the same-tokenizer teacher** (unblocked by
   7.3-B): decoupled top-K KD at ~32× denser signal/token; measured on the
   ladder first (G5).
4. **Reasoning-density up, knowledge via memory/tools** — the
   Inkling-Small datapoint (§6.2) licenses leaning the anneal further into
   math/code/reasoning; SimpleQA-style knowledge is Engram's and the tool
   registry's job, not the experts'.
5. **Reasoning-effort control via SFT data** (Nemotron / K3 / V4
   convergence): extend the reasoning-on/off contract to
   {off, low, high} by including truncated-trace completions — no
   architecture change, composes with the existing system-prompt contract.

### 7.6 Tier 3½ — post-training

1. **MoE-RL hygiene kit** (V4/V3.2 + GLM + Nemotron convergence): **Keep
   Routing** (enforce sampling-time expert paths during updates), **router
   frozen during RL**, keep-sampling-mask, unbiased-KL estimator,
   off-policy negative masking, deterministic top-k in rollouts.
2. **Simultaneous multi-env RLVR with difficulty curriculum** (Nemotron
   found staged RL less stable and more hackable) + **group-relative
   length-control reward** (−30% verbosity free).
3. **Consolidate specialists via OPD/MOPD, never weight-merge them**
   (V4, K3, GLM cross-stage distillation, Xiaomi MOPD numbers). Same-run
   souping stays (0.4).
4. **QAT from SFT onward on routed experts** (K2-Thinking→K3 pattern),
   reporting all evals at deployed precision; extends the existing int4-KV
   + AlphaQ deployment story.

### 7.7 Tier 4 — deployment (mostly unchanged from v6 plans)

Spec-decode via loop-3 draft (measure acceptance at last), per-loop
self-distillation to raise it (§14.5), early-exit harvest (§14.6),
selective FP8 PTQ keeping attention anchors BF16 (Nemotron pattern),
AlphaQ + TurboQuant as before. NVFP4 *pretraining* parked for v8
(Blackwell-only).

## 8. Proposed v7 shape (strawman — for the ladder to confirm, not a commitment)

```
dim 1536, 3 physical blocks × 6 loops (18 effective layers)   [unchanged]
GQA 24q/8kv head 64, KDV compressed-latent cache, QK-norm     [unchanged]
RoPE @ 4096 ctx (8K-capable)                                  [unchanged]
Routed experts: 32 × h960 per block, top-8 (25% density)      [re-grained]
Shared expert:  1 × h2816 per block                           [unchanged]
Router: sqrt(softplus) + Quantile-Balancing bias + z-loss
        + seq-balance 1e-4                                    [QB new]
HRA rank 256, native, per effective layer                     [unchanged]
mHC: off, OR n_hc=4 @ 3–5 Sinkhorn iters if it clears G1      [cost-fixed]
SiTU-GLU experts; per-head Muon; V4 Muon recipe               [graduated]
MTP: 1 shared-param head, loss 0.3 → 0.1 at decay             [slimmed]
Tokenizer: SmolLM3 49,152 (pending G2 bake-off)               [replaced]
Optional: Engram sidecar @ ~25M GPU / larger CPU-offloaded    [gated]
```

Parameter arithmetic (same formulas as `compute_budget.py`; regenerate
there before locking anything):

| component | v6 | v7 strawman |
|---|---|---|
| Tied embedding | 100.7M | **75.5M** (49,152 × 1536) |
| Attention × 3 | 17.3M | 17.3M |
| Shared experts | 38.9M | 38.9M |
| Routed experts | 424.7M (3×8×h3840) | 424.7M (3×32×h960) |
| HRA | 14.2M | 14.2M |
| MTP | 4.7M (2 heads) | ~2.4M (1 shared) |
| mHC + router + misc | ~1.0M | ~0.2–1.1M |
| **Total physical** | **601M** | **~574M** (+~25M Engram option → ~600M) |
| **Active/token** | **278M** | **~253M** |

Memory check against requirement 1 (fp32 masters + grads, fp32 Muon
momentum, AdamW on embed/norms): optimizer+weights floor ~7.2GB (v6:
~7.6GB); activations at batch 6 × seq 4096 with grad-ckpt ≈ v6's (same
dim/loops; less if mHC off) → **~55–58GB peak = comfortable on H100 80GB,
roomy on RTX PRO 6000 96GB** (batch 8+ or in-loop eval headroom). The
freed embedding params are the Engram budget — or stay unspent as margin.

Loops × blocks: 3×6 stays the default; the ladder gets one 4×4 and one
3×5-with-loop-curriculum slot (§14.4 loop-count curriculum; the KV probe's
"converged by loops 4–5" finding motivates both).

## 10. What v7 is NOT

- **Not a context-length race.** 1M-token tricks (DSA indexers, IndexShare,
  HCA) solve problems OSRT does not have at 4–8K. Revisit only if the
  north-star changes; V4's SWA+compressed-global pattern is the noted
  route (§4.3.3).
- **Not a hybrid-SSM rewrite.** KDA/Mamba-2 hybrids are real wins at 128K+
  contexts, but GLM's ablation shows half-recipes lose retrieval, the full
  recipe is a kernel-engineering project, and at 8K the payoff is small.
  One stretch slot *may* try a KDA block inside the recursion — only if the
  ladder is ahead of schedule.
- **Not NVFP4/FP8 pretraining.** Blackwell-only (NVFP4) or blocked by
  `_grouped_mm` + shape economics (FP8, §12 of the 2026-07-26 note — that
  rejection stands).
- **Not adaptive top-k.** E=32 makes it *eligible*; the fixed-shape
  compile objection still wins. Re-read §8 of the 2026-07-26 note first.
- **Not multimodal, not agent-swarm, not a bigger model.** The budget
  reality (§2.4) is unchanged; v7's job is to make the same-class model
  *good*, with a cleaner path for tokens to become capability.
- **Not weight-merging of specialists** (policy-space consolidation only).
